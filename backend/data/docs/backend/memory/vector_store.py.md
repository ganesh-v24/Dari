# backend\memory\vector_store.py — Lightweight in-memory vector store for text chunks

## Overview
This file implements a simplified vector storage system used for Retrieval-Augmented Generation (RAG) within the Dari project. Instead of relying on heavy embedding models or external databases, it uses a TF-IDF-inspired bag-of-words approach with cosine similarity to retrieve relevant text chunks based on keyword overlap.

## Architecture Role
- **Layer**: Memory / Persistence.
- **Pattern**: Singleton (via the exported `vector_store` instance).
- **Dependency direction**: Receives calls from higher-level memory management services or agent reasoning loops; calls the local filesystem for persistence.

## Key Concepts (Basics → Advanced)

1. **Tokenization**: The system converts raw text into a set of unique, lowercase, alphanumeric tokens using regular expressions. This removes noise and ensures that "Apple" and "apple" are treated as the same entity.
2. **Bag-of-Words Representation**: Each document is stored as a list of tokens. This ignores word order but captures the presence of key terms.
3. **Cosine Similarity (Set-based)**: The system calculates similarity by measuring the intersection of the query token set and the document token set, normalized by the square root of their lengths.
   - Formula: $\text{similarity} = \frac{|A \cap B|}{\sqrt{|A| \cdot |B|}}$
4. **JSON Persistence**: To maintain state across restarts, the store serializes the entire document list to a local JSON file (`vector_store.json`).

## Gotchas & Extension Points
- **Performance**: Since `search` performs a linear scan ($O(N)$) over all documents, it will slow down significantly as the number of chunks grows. For larger datasets, this should be replaced with a proper vector database (e.g., FAISS, ChromaDB).
- **Semantic Gap**: Because it uses keyword overlap rather than dense embeddings, it cannot find documents that are semantically related but use different vocabulary (e.g., "dog" will not match "canine").
- **Extension Point**: To improve accuracy, the `_tokenize` method could be extended to include a "stop-word" filter to remove common words (e.g., "the", "is", "at") that inflate similarity scores without adding meaning.
- **Concurrency**: The current implementation is not thread-safe; simultaneous writes to the JSON file from different threads could lead to data corruption.
