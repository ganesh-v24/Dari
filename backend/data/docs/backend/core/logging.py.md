# backend\core\logging.py — Centralized logging configuration for the Dari system

## Overview
This file initializes and configures the global logging system for the backend. It leverages the `loguru` library to provide a standardized log format and ensures cross-platform compatibility for character encoding, specifically addressing emoji rendering on Windows consoles.

- **Layer**: Core Utility / Infrastructure.
- **Pattern**: Singleton Configuration (via `loguru`'s global logger).
- **Dependency direction**: This is a foundational module; it is called during the application bootstrap phase and is used by all other modules in the system to emit logs.

## Key Concepts (Basics → Advanced)
1. **Loguru Integration**: Instead of using the standard Python `logging` module, the system uses `loguru` for its simplified API and powerful formatting capabilities.
2. **Sink Management**: The `logger.remove()` call clears all default handlers to prevent duplicate log entries, ensuring that only the custom-defined sink is active.
3. **Encoding Normalization**: On Windows platforms, the standard `sys.stdout` often uses `cp1252` encoding, which crashes or mangles output when encountering emojis (common in AI agent logs). The code wraps the stdout buffer in a `TextIOWrapper` with `utf-8` encoding to ensure stability.
4. **Standardized Formatting**: A consistent pipe-delimited format (`{time} | {level} | {message}`) is enforced across the entire application for easier parsing by developers or log aggregators.

## Public API / Exports

## Data Flow
1. **Initialization**: The application entry point calls `setup_logging()`.
2. **Cleanup**: `logger.remove()` wipes existing handlers.
3. **Stream Selection**: The system checks `sys.platform`; if `"win32"`, it creates a UTF-8 wrapper around `sys.stdout.buffer`.
4. **Sink Attachment**: `logger.add()` attaches the determined stdout stream to the logger with the specified format and level.
5. **Execution**: Other modules import `from loguru import logger` and emit logs, which flow through this configured pipeline to the console.

- **Log Level**: The level is currently hardcoded to `"INFO"`. To make this configurable, one could modify `setup_logging` to accept a `level` argument or read from an environment variable.
- **File Persistence**: Currently, logs are only sent to `stdout`. To add file-based logging (e.g., `app.log`), a second `logger.add()` call should be implemented within `setup_logging`.
- **Performance**: While `loguru` is efficient, high-frequency logging in the reasoning loops of the AI agents may impact performance; consider adding a `DEBUG` level toggle for production environments.
