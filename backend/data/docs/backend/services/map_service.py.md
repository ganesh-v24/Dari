# backend\services\map_service.py — Geospatial routing and geocoding service

## Overview
This file provides the core geospatial logic for the Dari system, enabling the conversion of human-readable location names into coordinates and calculating the shortest walkable paths between them. It leverages OpenStreetMap data to provide real-world navigation reasoning.

## Architecture Role
- **Layer**: Service
- **Pattern**: Utility/Service Provider
- **Dependency direction**: Receives calls from API controllers (e.g., a routing endpoint); calls external geospatial libraries (`osmnx`, `networkx`, `geopy`).

## Key Concepts (Basics → Advanced)
1. **Geocoding**: The process of converting a string address or place name (e.g., "Central Park") into geographic coordinates (latitude, longitude) using the `Nominatim` engine.
2. **Graph-Based Routing**: The map is treated as a mathematical graph where intersections are nodes and roads/paths are edges. The service downloads a specific subgraph based on a bounding box.
3. **Bounding Box (BBox)**: To avoid downloading an entire city's map, the service calculates a rectangular area (North, South, East, West) that encompasses both the start and end points with a 0.01-degree padding.
4. **Dijkstra's Algorithm**: Through `nx.shortest_path`, the system finds the path with the minimum total `length` weight between the nearest network nodes to the requested coordinates.

## Data Flow
1. **Input**: `find_shortcut` receives `start_name` and `end_name`.
2. **Geocoding**: `get_coords` is called for both names $\rightarrow$ returns `(lat, lon)` pairs.
3. **Spatial Filtering**: A bounding box is calculated based on the min/max of the coordinates.
4. **Graph Acquisition**: `ox.graph_from_bbox` downloads the walkable network for that specific area.
5. **Node Mapping**: `ox.distance.nearest_nodes` snaps the raw coordinates to the closest valid nodes on the OpenStreetMap graph.
6. **Pathfinding**: `nx.shortest_path` computes the sequence of nodes minimizing the `length` attribute.
7. **Transformation**: Node IDs are mapped back to `[lat, lon]` lists.
8. **Output**: A dictionary containing `success` status, coordinates, and the `route` array.

## Gotchas & Extension Points
- **BBox Limitations**: The current padding (0.01 degrees) is roughly 1.1km. If the start and end points are very far apart, the bounding box might be too small or the graph download might be too large/slow.
- **Network Connectivity**: `ox.graph_from_bbox` requires an active internet connection to fetch data from Overpass API.
- **Walkability**: The `network_type='walk'` filter ensures the route is walkable, but it does not account for real-time obstacles or accessibility (e.g., stairs).
- **Extension Point**: The `weight='length'` parameter in `nx.shortest_path` could be replaced with a custom weight (e.g., "time" or "safety") if the graph attributes are enriched.
