# backend\services\llm_service.py — LLM-powered intent classification and query analysis

## Overview
This file serves as the primary interface between the Dari backend and the Ollama LLM provider. Its main purpose is to transform raw user natural language input into structured JSON intents, allowing the system to decide whether to trigger navigation routing, document retrieval, or a general chat response.

## Architecture Role
- **Layer**: Service
- **Pattern**: Adapter / Gateway (wraps the Ollama API)
- **Dependency direction**: Receives calls from the API/Controller layer; calls the external Ollama REST API via `httpx`.

## Key Concepts (Basics → Advanced)
1. **Intent Classification**: The service uses a "System Prompt" to force the LLM to act as a classifier. Instead of free-form conversation, the LLM is instructed to map inputs into one of three specific intents: `route`, `document`, or `chat`.
2. **Structured Output (JSON)**: To ensure the backend can programmatically handle the response, the service mandates a strict JSON schema.
3. **Deterministic Generation**: The `temperature` is set to `0.0` in the payload. This minimizes randomness and ensures that the LLM consistently produces the same JSON structure for the same input.
4. **Resilience Parsing**: The service includes a cleaning step to handle "Markdown leakage," where LLMs occasionally wrap JSON responses in ```json ... ``` blocks despite instructions to the contrary.

1. **Input**: A raw string `user_message` is passed into `analyze_user_query`.
2. **Payload Construction**: The message is bundled with the `SYSTEM_PROMPT` and model configuration (`gemma4:31b:cloud`).
3. **External Request**: An asynchronous POST request is sent to the `OLLAMA_URL`.
4. **Response Extraction**: The raw string content is extracted from the Ollama response object.
5. **Sanitization**: Any markdown code fences (`` ```json ``) are stripped from the content.
6. **Parsing**: The string is converted into a Python dictionary via `json.loads`.
7. **Output**: A dictionary containing `intent` and relevant keys (`start`, `end`, `query`, or `message`) is returned.

## Gotchas & Extension Points
- **Hardcoded Configuration**: `OLLAMA_URL` and `MODEL_NAME` are currently constants. For production, these should be moved to an `.env` file or a configuration manager.
- **Timeout Limits**: The `timeout=30.0` may be insufficient for very large models or slow hardware, potentially leading to `TimeoutException`.
- **Prompt Fragility**: If the system requirements grow (e.g., adding a "settings" intent), the `SYSTEM_PROMPT` must be manually updated and tested for regressions.
- **Error Fallbacks**: The service currently returns a "chat" intent as a fallback for `JSONDecodeError`, which might mask underlying prompt engineering issues.
