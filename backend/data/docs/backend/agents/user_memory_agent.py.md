The `UserMemoryAgent` is a specialist agent responsible for the persistence and retrieval of user-specific data. It tracks navigation history, stores explicit user preferences, and maintains a list of frequently visited or searched locations to personalize the navigation experience.

## Key Concepts (Basics → Advanced)

1. **JSON Persistence**: The agent uses a simple flat-file JSON store (`user_memory.json`) to ensure that user preferences and history persist across application restarts.
2. **Automatic Favorite Tracking**: Whenever a route is recorded via `record_route`, the start and end locations are automatically added to the `favorite_places` list if they aren't already present.
3. **Capped History**: To prevent the memory file from growing indefinitely, the `route_history` is capped at the 50 most recent entries.
4. **Regex-Based Intent Parsing**: The agent uses a regular expression (`_REMEMBER_RE`) to detect "remember" commands, allowing it to extract preferences from natural language strings (e.g., "Remember that I prefer scenic routes").
5. **Keyword-Based Retrieval**: The `execute` method implements a keyword-matching system to route user queries to specific memory retrieval functions (history, preferences, or favorites).

2. **Parsing**: 
    - The agent checks the string against `_REMEMBER_RE` for preference updates.

## Gotchas & Extension Points
- **Naive Key Extraction**: The current preference logic simply takes the first word of the preference string as the key (e.g., "scenic routes" $\rightarrow$ key: "scenic"). This could be improved by using an LLM for entity extraction.
- **Concurrency**: The agent uses synchronous file I/O (`write_text`). In a high-concurrency environment, this could lead to race conditions or blocking; consider moving to an async database or `aiofiles`.
- **Case Sensitivity**: While favorite places are checked using `.lower()`, preference keys are case-sensitive based on the first word of the input.
- **Extension Point**: The `_load` and `_save` methods can be overridden to support a database (like SQLite or MongoDB) instead of a JSON file for larger-scale deployments.
