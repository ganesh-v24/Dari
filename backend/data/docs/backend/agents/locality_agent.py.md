# backend\agents\locality_agent.py — Agent for providing cultural and historical facts about locations

## Overview
The `LocalityAgent` is a specialist agent designed to enrich the user experience by providing "fun facts," historical context, and cultural notes about specific geographical locations. It leverages a combination of regex-based entity extraction, geocoding verification, and an LLM (via Ollama) to generate conversational, tour-guide-style responses.

## Key Concepts (Basics → Advanced)

1. **Agent Registration**: Upon instantiation, the agent registers itself with the global `registry` under the key `"locality"`, allowing the system to route location-based queries to this specific class.
2. **Entity Extraction**: The agent uses a two-tier approach to identify the subject of the query:
    - **Primary**: A regular expression (`_PLACE_RE`) that looks for common linguistic patterns (e.g., "tell me about...", "history of...").
    - **Fallback**: A utility function `extract_place_names` that identifies capitalized sequences.
3. **Geocoding Verification**: Before querying the LLM, the agent attempts to resolve the extracted place name to coordinates using `get_coords`. While the coordinates aren't passed to the LLM, this step serves as a validation check to ensure the place actually exists.
4. **LLM Integration**: It uses a system prompt (`LOCALITY_PROMPT`) to constrain the LLM's persona to a "witty local tour guide," ensuring the output is formatted as a numbered list with a conversational tone.
5. **Graceful Degradation**: The `execute` method wraps the LLM call in a try-except block. If the AI service is unavailable, it returns a set of generic, hard-coded facts to prevent the user from seeing a raw error.

## Gotchas & Extension Points

- **Hardcoded LLM Config**: The `OLLAMA_URL` and `MODEL_NAME` are hardcoded constants. These should be moved to an environment configuration file for production deployments.
- **Regex Limitations**: The `_PLACE_RE` is basic. It may fail on complex sentences or non-English queries. Extending this to use a proper NER (Named Entity Recognition) model would improve accuracy.
- **Geocoding Utility**: Currently, `get_coords` is used only for logging/verification. An extension point would be to pass the actual coordinates or the "official" name returned by the map service into the LLM prompt for higher precision.
- **Timeout**: The `httpx` client has a fixed 30-second timeout, which may be too short for larger LLM models or slow hardware.
