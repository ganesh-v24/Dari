# backend\agents\route_agent.py — Specialist agent for geocoding and walking route discovery

## Overview
The `RouteAgent` is a specialized component of the Dari system responsible for translating location-based natural language instructions into geographic coordinates and navigable paths. It acts as the bridge between the agentic reasoning layer and the underlying map services, ensuring that route requests are geocoded, calculated, and cached for efficiency.

## Key Concepts (Basics → Advanced)

### 1. Instruction Parsing
The agent employs a tiered parsing strategy to understand user intent:
- **Structured Commands**: It first looks for strict pipe-delimited formats (`ROUTE|start|end` or `FIND|place`). This allows the system's high-level planner to communicate with the agent without ambiguity.
- **Naive Extraction**: If structured commands fail, it uses `extract_place_names` from the utility layer to attempt to guess locations from raw text.

### 2. Geocoding and Routing
- **Single Point (`_handle_find`)**: Resolves a single place name to coordinates using `get_coords`.
- **Pathfinding (`_handle_route`)**: Resolves two points and calculates the shortest walking path via `find_shortcut`.

### 3. Memoization via RouteMemory
To avoid redundant API calls to OpenStreetMap/OSMNX and reduce latency, the agent checks `route_memory` before executing a search. It stores both single-point geocoding results and full route paths, keyed by the start and end location strings.

## Data Flow

1. **Input**: An `instruction` string is passed to `execute()`.
2. **Parsing**: 
    - `_parse_route` $\rightarrow$ returns `(start, end)` if matched.
    - `_parse_find` $\rightarrow$ returns `place` if matched.
    - `extract_place_names` $\rightarrow$ returns a list of strings as a fallback.
3. **Cache Check**: The agent queries `route_memory.get(start, end)`. If a hit occurs, the cached data is returned immediately.
4. **Service Execution**: 
    - For finds: `get_coords(place)` is called.
    - For routes: `find_shortcut(start, end)` is called.
5. **Persistence**: Successful results are saved back to `route_memory.set()`.
6. **Output**: A dictionary containing `type` (either `"route"` or `"chat"`), `content` (human-readable text), and optional `data` (coordinates/path).

## Gotchas & Extension Points
- **Parsing Fragility**: The `_parse_route` and `_parse_find` methods rely on a strict `|` delimiter. If the planner's output format changes, these methods must be updated.
- **Coordinate Accuracy**: The agent assumes `get_coords` returns a valid result; if the map service returns an ambiguous location, the agent currently treats it as a failure.
- **Extension Point**: To support different transport modes (e.g., cycling, driving), the `_handle_route` method could be extended to accept a `mode` parameter and pass it down to `find_shortcut`.
- **Memory Eviction**: The current implementation does not show a TTL (Time-to-Live) for `route_memory`, which may lead to stale data if map networks change.
