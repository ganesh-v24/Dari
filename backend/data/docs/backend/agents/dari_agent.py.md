## Overview
The `DariAgent` serves as the primary conversational interface and fallback handler for the Dari project. It manages non-specialized interactions such as greetings, help requests, and general small talk, ensuring the user has a friendly point of contact when a specific domain agent (like route or memory) is not required.

## Key Concepts (Basics → Advanced)
1. **Agent Registration**: Upon instantiation, the agent calls `registry.register("dari", self)`, allowing the system's central registry to map the keyword "dari" to this specific class instance.
2. **Instruction Parsing**: The agent implements a basic protocol to handle routed messages. It checks for a `CHAT|` prefix, which is a convention used by the `PlannerAgent` to signal that the input is intended for general conversation rather than a specialized task.
3. **Keyword-Based Intent Matching**: Instead of using a heavy LLM for every greeting, the agent uses lightweight string matching (`msg_lower`) to identify common intents:
    - **Greetings**: Matches specific welcome words.
    - **Farewells**: Matches goodbye keywords.
    - **Help**: Matches queries regarding capabilities.
4. **Fallback Mechanism**: If no keywords match, the agent provides a "friendly fallback" response, guiding the user back toward the system's core capabilities (Routes, Locality, Memory, Docs).
