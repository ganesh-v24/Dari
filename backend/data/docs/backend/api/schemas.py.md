## Overview
This file defines the request and response schemas for the Dari API using Pydantic models. It ensures strict type validation and provides a structured contract between the frontend client and the backend reasoning system.

## Architecture Role
- **Layer**: API / Interface Layer.

- **Dependency direction**: This file is a leaf dependency; it is imported by API route handlers (controllers) to validate incoming JSON payloads and serialize outgoing responses.

## Key Concepts (Basics → Advanced)
1. **Pydantic BaseModels**: All schemas inherit from `BaseModel`, providing automatic runtime type checking and JSON serialization.
2. **Field Metadata**: The use of `Field(..., description=...)` serves as both a validation constraint and internal documentation for the API's expected inputs.
3. **Polymorphic Responses**: The `ChatResponse` model uses a `type` field (`'chat' | 'route' | 'document'`) to allow the frontend to dynamically determine how to render the response (e.g., as a text bubble, a map route, or a document list).
4. **Optionality and Defaults**: Use of `Optional` and `default_factory` (e.g., in `RouteResponse.route`) ensures the API doesn't crash when returning partial data or empty lists.

## Data Flow
1. **Ingress**: A JSON payload arrives at an API endpoint.
2. **Validation**: FastAPI/Pydantic maps the JSON to a `Request` model (e.g., `ChatRequest`), validating that required fields like `message` are present and are strings.
3. **Processing**: The validated model is passed to the business logic/agent layer.
4. **Egress**: The business logic returns data which is packed into a `Response` model (e.g., `RouteResponse`).
5. **Serialization**: Pydantic converts the model back into a JSON string for the HTTP response.

## Gotchas & Extension Points
- **Coordinate Format**: `RouteResponse.route` is defined as `list[list[float]]`. Developers must ensure the order is consistently `[latitude, longitude]` to avoid mapping errors.
- **Extending Response Types**: To add new agent capabilities (e.g., "Search" or "Settings"), a new `Request`/`Response` pair should be added here and the `ChatResponse.type` description updated.
- **Strictness**: Since `Field(..., ...)` is used, these fields are mandatory. If an optional input is needed, it must be wrapped in `Optional` with a default value of `None`.
