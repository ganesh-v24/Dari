# backend\api\routes.py — API Route Definitions for the Dari System

## Overview
This file defines the REST API endpoints for the Dari project using FastAPI. It serves as the entry point for external clients to interact with the system's navigation reasoning capabilities, providing interfaces for system metadata, shortcut calculations, and agentic chat interactions.

## Architecture Role
- **Layer**: API / Controller
- **Pattern**: Router (FastAPI `APIRouter`)
- **Dependency direction**: Receives HTTP requests from the client; calls `PlannerAgent` for reasoning, `find_shortcut` from the map service for routing, and the `registry` for agent discovery.

## Key Concepts (Basics → Advanced)
1. **Endpoint Routing**: Uses `APIRouter` to map HTTP methods (GET, POST) and paths to specific Python functions.
2. **Schema Validation**: Leverages Pydantic models (`ChatRequest`, `RouteResponse`, etc.) to ensure incoming request bodies and outgoing responses adhere to a strict data contract.
3. **Service Orchestration**: The `/chat` endpoint demonstrates the "Orchestrator" pattern, where the `PlannerAgent` acts as the central brain to decompose user queries and coordinate responses.
4. **Error Mapping**: Translates internal service errors (e.g., a dictionary containing an `"error"` key) into standard HTTP exceptions (`HTTPException`) with appropriate status codes.

## Public API / Exports
| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/info` | GET | Returns basic service metadata and a list of active agents. |
| `/agents` | GET | Returns a detailed list and count of all registered agents. |
| `/shortcut` | POST | Calculates a shortcut between two locations using `find_shortcut`. |

## Data Flow
1. **Request Entry**: A client sends an HTTP request (e.g., a POST to `/chat` with a `ChatRequest` JSON body).
2. **Validation**: FastAPI validates the JSON against the Pydantic schema.
3. **Processing**:
    - For `/shortcut`: The request is passed to `find_shortcut` $\rightarrow$ result is checked for errors $\rightarrow$ mapped to `RouteResponse`.
    - For `/chat`: The message is passed to `planner.execute()` $\rightarrow$ the agentic loop processes the query $\rightarrow$ result is mapped to `ChatResponse`.
4. **Response**: The final Pydantic model is serialized to JSON and returned to the client.

## Gotchas & Extension Points
- **Synchronous vs Asynchronous**: Note that `/chat` is defined as `async def` because `planner.execute` is awaited, whereas `/shortcut` is a standard `def`. Ensure any new service calls are handled with the correct concurrency pattern.
- **Error Handling**: Currently, `/shortcut` checks for an `"error"` key in a dictionary. This could be extended to a more robust custom Exception hierarchy for better granularity.
- **Extension Point**: To add new agent capabilities, one can add new routes here that call specific agents from the `registry` instead of routing everything through the `PlannerAgent`.
