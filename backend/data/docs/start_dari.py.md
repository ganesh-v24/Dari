# start_dari.py — Orchestration script for launching the Dari full-stack environment

## Overview
`start_dari.py` serves as the primary entry point for developers to boot the entire Dari system. It automates the simultaneous launch of the FastAPI backend and the React/Vue frontend, managing their processes and aggregating their logs into a single terminal stream.

## Architecture Role
- **Layer**: Infrastructure / Tooling.
- **Pattern**: Process Orchestrator.
- **Dependency direction**: Acts as a wrapper that invokes external system processes (`uvicorn` and `npm`). It does not import internal project logic but manages the execution environment for the `backend` and `web` directories.

## Key Concepts (Basics → Advanced)
1. **Subprocess Management**: The script uses `subprocess.Popen` to launch the backend and frontend as independent child processes. This allows the Python script to maintain control over the lifecycle of both services.
2. **Non-blocking I/O**: By setting `stdout=subprocess.PIPE` and `stderr=subprocess.STDOUT`, the script captures all output from the child processes without letting them block the main execution thread.
3. **Concurrent Log Streaming**: Since reading from a process pipe is a blocking operation, the script employs `threading.Thread`. Two separate threads are spawned to continuously read and print lines from the backend and frontend, prefixing them with `[BACKEND]` and `[FRONTEND]` for clarity.
4. **Graceful Termination**: The script wraps the main loop in a `try...except KeyboardInterrupt` block, ensuring that when a user presses `Ctrl+C`, both child processes are explicitly terminated via `.terminate()` to prevent "zombie" processes from occupying ports 8000 and 5173.

## Data Flow
1. **Initialization**: The script identifies the absolute paths for the `backend` and `web` directories.
2. **Process Spawning**: 
    - `start_backend()` $\rightarrow$ executes `python -m uvicorn app.main:app`.
    - `start_frontend()` $\rightarrow$ executes `npm.cmd run dev`.
3. **Log Aggregation**: 
    - `backend_proc` $\rightarrow$ `t1 (Thread)` $\rightarrow$ `stream_output` $\rightarrow$ Console.
    - `frontend_proc` $\rightarrow$ `t2 (Thread)` $\rightarrow$ `stream_output` $\rightarrow$ Console.
4. **Lifecycle Maintenance**: The main thread enters a `while True` sleep loop to keep the process alive until a `KeyboardInterrupt` is received.

## Gotchas & Extension Points
- **Windows Specificity**: The script explicitly calls `npm.cmd`, which is required for Windows environments. On Linux/macOS, this may need to be changed to `npm`.
- **Port Conflicts**: The script assumes ports `8000` and `5173` are available. If these ports are occupied, the child processes will crash, but the Python script may continue to run.
- **Extension Point**: To support production environments, one could extend this script to check for an `.env` file or validate that `node_modules` and `venv` are installed before attempting to start the processes.
- **Extension Point**: Integration with a process manager like `supervisord` or `docker-compose` would be the recommended path for scaling beyond a local development script.
